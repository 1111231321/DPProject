
Общие сведения

Наименование проекта: Веб-приложение агрегатор туристических услуг и справочной информации «TourBird».
Назначение и цель проекта: Создание единого информационного окна для самостоятельных путешественников, объединяющего поиск авиабилетов, подбор вариантов размещения (жилья) и интерактивный справочник по подготовке к поездке (визовые требования, правила провоза багажа, чек-листы документов).
Сроки разработки: с 11.11.2026 по 31.01.2027 

2. Роли и сценарии использования

• Пользователь (турист): Неавторизованный посетитель сайта. Имеет полный доступ ко всем инструментам поиска, фильтрации справочных материалов, интерактивным чек-листам и переходу на внешние площадки бронирования по партнёрским ссылкам.
• Администратор (владелец системы): Управляет наполнением собственной базы данных (актуализация визовых правил, добавление статей в «Памятку туриста», управление локальной базой объектов жилья) через защищённые эндпоинты API.

3. Функциональные требования


3.1. Клиентская часть (Frontend)

• Главная страница:
	Единая форма поиска с переключением вкладок («Авиабилеты» / «Жильё»).
	Поля формы для авиабилетов: город/аэропорт вылета (с автодополнением), город прилёта, дата вылета, дата возвращения, количество пассажиров и класс обслуживания.
	Поля формы для жилья: город/направление, даты заезда и выезда, количество гостей.
	Валидация введённых данных перед отправкой запроса (проверка заполнения обязательных полей, корректности дат).
	Блок популярных направлений и быстрый переход в раздел справочника.
• Страница результатов поиска:
	Отображение списка найденных авиабилетов (цена, авиакомпания, время вылета/прилёта, количество пересадок) с кнопкой перехода на покупку.
	Отображение карточек доступного жилья (фото, название, стоимость, краткое описание) с переходом на внешнюю площадку бронирования.
	Фильтрация и сортировка выдачи (по цене, времени в пути, наличию пересадок).
• Раздел «Памятка туриста / Что нужно для перелёта»:
	Интерактивный справочник с фильтрацией по странам и категориям (документы, виза, таможенные правила, нормы провоза багажа и ручной клади).
	Интерактивный чек-лист сборов с возможностью отмечать собранные вещи и документы (сохранение состояния в localStorage браузера).

3.2. Серверная часть (Backend на Node.js)

• Проксирование запросов к внешним API:
	Интеграция с API партнёрской сети Travelpayouts (инструменты Aviasales) для получения актуальных цен на авиабилеты и генерации корректных партнёрских ссылок.
	Интеграция с API сервисов бронирования жилья (Островок / Суточно.ру) либо работа с локальной базой объектов с формированием ссылок перехода на внешние площадки.
	Безопасное хранение всех API-токенов и ключей на стороне сервера в файле конфигурации (.env) без передачи на клиент.
• Собственный REST API:
	Эндпоинты для получения, фильтрации и поиска справочной информации (страны, правила, чек-листы) из базы данных.
	Административные методы (CRUD) для обновления справочных данных.
• Оптимизация и кэширование:
	Реализация серверного кэширования ответов от внешних API (на заданный интервал времени) для снижения количества запросов и ускорения выдачи результатов пользователю.

4. Нефункциональные требования и стек технологий

• Клиентская часть: Семантический HTML5, CSS3 (Flexbox/Grid), нативный JavaScript (ES6+, Fetch API).
• Серверная часть: Node.js, фреймворк Express.js (или Fastify).
• База данных: PostgreSQL или MongoDB (для хранения справочника туриста, чек-листов и локальной базы жилья).
• Адаптивность и кроссбраузерность: Корректное отображение на десктопах (от 1280px), планшетах (768px) и мобильных устройствах (от 360px) в актуальных версиях Chrome, Firefox, Safari, Яндекс.Браузера и Edge.
• Отказоустойчивость: Корректная обработка ошибок и отображение информативных уведомлений пользователю при временной недоступности внешних API, а также индикация процесса загрузки (лоадеры).

6. Критерии приёмки и оценки работоспособности

• Формы поиска корректно валидируют данные, отправляют запросы на Node.js-сервер и отображают актуальные результаты.
• Секретные ключи внешних API полностью скрыты от клиентской части и хранятся в переменных окружения на сервере.
• Переход по карточкам билетов и жилья корректно открывает целевые страницы партнёрских площадок с передачей параметров поиска.
• Раздел «Памятка туриста» корректно фильтрует данные из базы и сохраняет прогресс по чек-листу.
• Веб-приложение развёрнуто на удалённом сервере и доступно по публичной ссылке для демонстрации на защите выпускной квалификационной работы.
